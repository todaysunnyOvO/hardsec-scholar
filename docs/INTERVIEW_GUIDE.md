# HardSec Scholar 面试演示指南

## 一句话介绍

HardSec Scholar 是一个面向硬件安全英文论文的小型本地 Agentic RAG：它不仅回答问题，还展示检索计划和重试轨迹，并要求每个关键结论绑定可回看的论文页码证据。

## 7 分钟演示流程

### 0:00–0:45：问题与边界

- 场景：个人手中约 10 篇侧信道攻击、体系结构安全和模糊测试论文，需要快速查机制、威胁模型和实验设置。
- 普通聊天模型的问题：不知道用户的私有语料，答案来源难核验。
- 本项目边界：只查本地论文、默认不联网、证据不足时拒答。

### 0:45–1:45：论文库

打开 Paper library，展示 10 篇论文的 `indexed` 状态、页数和切片数量。任选一篇解释：PDF 经页码保留的解析与章节感知切分后，元数据写入 SQLite，向量写入 Chroma。

### 1:45–4:15：主问答链路

优先选择一道需要多步检索或跨论文综合的问题，不要只演示标题中就能直接命中的事实题。提问后依次指出：

1. 问题分类与多个检索查询；
2. Dense/BM25 候选、RRF 融合和重排；
3. 证据不足时的有界查询改写；
4. 最终答案的 Evidence ID；
5. 点击引用查看论文、章节、页码与原文；
6. 右侧轨迹只显示安全摘要，不显示模型隐藏思维链。

可准备的问题类型：

- 威胁模型：攻击者需要控制或观察哪些硬件资源，论文假设了哪些权限？
- 机制：某种反馈或输入生成机制如何提高发现漏洞的能力？
- 比较：两篇论文的观测信号、攻击前提或实验平台有何不同？

演示前应在你自己的 10 篇论文上预跑一次问题，确认论文名称和表述与界面一致；不要背诵评测参考答案。

### 4:15–5:00：拒答与安全性

询问一个论文没有覆盖的问题。解释系统的 fail-closed 路径：证据评价、最大检索重试、引用完整性检查和语义引用验证任何关键环节失败，都可能进入修复或拒答，而不是补写无来源内容。

### 5:00–6:15：对照实验

展示 `docs/EVALUATION_RESULTS.md`：10 篇论文、30 题、Dense Baseline 与 Agentic RAG 在相同完整语料上比较。

- Agentic Recall@10：0.7870，Baseline：0.7346。
- Agentic 全轮次金标准切片召回：0.8519，Baseline：0.7346。
- Agentic 平均延迟 8.2398 秒，Baseline 2.3350 秒。
- Agentic 回答/拒答正确率 0.9000，Baseline 0.9667。

核心结论：Agent 提高了搜索覆盖，尤其改善威胁模型类问题，但没有自动转化为全面更好的最终答案，并带来约 3.5 倍延迟与 2.5 倍 token。项目价值在于量化并暴露这个权衡，而不是只展示挑选过的成功样例。

### 6:15–7:00：工程总结

- LangGraph 把检索重试和答案修复拆成两个有上限的循环，防止无限调用。
- LLM 与 Embedding 走 OpenAI 兼容协议，可分别接 DeepSeek 和 SiliconFlow。
- 模型客户端延迟初始化；没有密钥时论文 CRUD 和历史查看仍可工作。
- 评测 runner 支持 JSONL 追加、成功项断点续跑和失败项补跑。

## 架构讲解主线

不要按文件逐个介绍。围绕一条问题链路讲：

```text
Question
  -> classify / expand
  -> Dense + BM25
  -> RRF + FlashRank
  -> evidence grade
  -> bounded rewrite (optional)
  -> cited structured answer
  -> citation integrity + semantic verification
  -> answer / repair / refusal
```

强调三个设计选择：

1. **为什么是 Agentic**：系统根据证据质量决定是否继续检索或修复，不是固定的一次 retrieve-then-generate。
2. **为什么可验证**：引用使用内部 Evidence ID 绑定确定的 paper/chunk/page，API 可回查原文。
3. **为什么有边界**：循环次数、查询数、上下文证据数都有上限，失败默认拒答。

## 常见追问与回答要点

### 为什么不用纯向量检索？

硬件安全论文同时包含自然语言概念和精确术语、缩写、漏洞名。Dense 擅长语义近似，BM25 擅长词项精确匹配；RRF 在不校准两类分数尺度的前提下融合排名，再由轻量 reranker 精排。

### Agentic RAG 和普通 RAG 的本质区别？

普通 Baseline 是一次 Dense top-10 后直接生成。Agentic 版本显式分类和扩展问题，评价证据是否足够，并在预算内改写查询；生成后还可因引用语义不成立而修复或拒答。

### 为什么 Agentic 的 Recall@5 和 MRR 反而低？

查询扩展提高了覆盖面，但也引入更多候选，使最相关切片不一定排在最前。当前结果说明下一步应优化路由和融合权重，而不是继续增加 Agent 节点。

### 为什么不用本地模型？

个人面试项目优先保证结构化输出和开发速度，当前采用兼容 API。模型访问被协议接口隔离，后续可以接支持稳定 function calling 的本地服务，但本版没有把未经验证的能力写成卖点。

### 如何防止幻觉？

无法绝对消除。项目通过限定本地语料、结构化 Claim、Evidence ID 完整性检查、LLM 语义引用复核、有界修复和最终拒答降低风险；评测也单独记录引用和拒答指标。

### 10 篇论文为什么还需要向量数据库？

10 篇是有意控制的个人项目规模。Chroma 提供持久化语义检索和稳定的 paper/chunk 元数据过滤；这个规模也让架构、引用和评测可以完整实现，而不是把时间花在分布式基础设施上。

### 数据是否会泄露？

文件和索引不由应用主动上传或公开部署，但提问与检索到的证据会发送给配置的 LLM/Embedding 服务商。因此“本地优先”不等于完全离线；处理未公开论文前必须确认供应商的数据政策。本项目不支持本地模型，所以不能声称内容从不离开设备。

### 如果扩展到上千篇论文？

需要异步摄取队列、增量索引、文档级路由、批量 Embedding、可观测的缓存与限流，并重新评估 Chroma/SQLite 的并发边界。先用检索指标确认瓶颈，再决定是否替换数据库。

## 诚实表述清单

- 说“内部 30 题评测集”，不要说“权威硬件安全基准”。
- 说“提高证据覆盖”，不要说“Agentic 全面优于 Baseline”。
- 说“本地持久化、调用云模型”，不要说“完全离线、论文绝不离开本机”。
- 说“降低幻觉并可回查”，不要说“彻底消除幻觉”。
- 说明成本估算不含 Embedding，供应商价格变化后需要重新计算。

## 演示前检查

```powershell
.\scripts\start_local.ps1
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

- 浏览器能打开 `http://localhost:3000`。
- 论文均为 `indexed`，至少一个问答已预跑。
- `.env`、API Key 和供应商控制台不出现在录屏或投屏中。
- 准备一题成功问答、一题拒答和评测报告，不依赖现场临时生成数据集。
- 演示结束后运行 `.\scripts\stop_local.ps1`。
